Generated by `code/evaluation/build_reports.py` from the public sample answers, the custom cases and the last run. Nothing here is hand-typed except the lists of failures and limits.

## What is measured and against what

The 32 public samples are the only cases with reference answers, so every accuracy number below is on those 32. The pipeline never reads `sample_output.csv`; only `evaluation/main.py` and this script do. The 518 evaluation cases have no reference answers.

## Checks on the 518 evaluation cases that need no gold

* **Contract:** every row is validated before `output.csv` is written (statuses, step keys, numbering, phase and operation order, evidence rules, no evidence after audit_at). The run refuses to write a file with a problem.
* **Determinism:** `output.csv` is byte-identical across runs and across PYTHONHASHSEED values (tested in a subprocess).
* **Hand audit:** 12 hidden cases drawn with a fixed seed (one per month February to September plus random fill) were read against their raw evidence; every disputed step led to a general fix, listed below.
* **Model cross-check:** the rule classifier, `qwen.qwen3-vl-235b-a22b` and `moonshotai.kimi-k2.5` agree on all 398 distinct request texts (`classifier_crosscheck.md`). The 10 cases classified NOT_APPLICABLE were read by eye.
* **Vision reader:** 15 of 15 PDF and screenshot files parse into the strict schema and every reported id and email is on the page (`document_benchmark.md`).

## Failures found and improvements made

| Failure | Improvement |
|---|---|
| Workflow matching depended on dict order, so output changed with PYTHONHASHSEED | Replaced the greedy rule with exact enumeration of consistent case-to-row assignments; links are made only when forced. A subprocess test runs the pipeline under different hash seeds. |
| Hand audit of 12 random hidden cases: support attachments and restore decisions were read wrongly | Fixed the state interpretation by resource type (attachments are deleted, a denied restore is BLOCKED), not case by case. Regression tests added. |
| Absence was assumed from a missing row instead of proved | Absence now needs a snapshot scope that covers the resource and was captured at or before audit_at. |
| Evidence captured after audit_at could be cited or could change a state | Admissibility is checked on every record and on every citation; the row verifier rejects late evidence. |
| Tombstones and linking: a name match could attach a stranger's record | Names never link. Only email, email hash, phone and user id do, as of the audit time. |
| SQL evidence: the sqlite authorizer rejected PRAGMA and REINDEX in snapshots | The authorizer now allows those statements; every SQL file indexes (94 of 94 files). |
| Vision reader returned a user reference as a resource id (user_20 instead of analytics_7438) | Prompt rule and example added; rerun correct. Schema widened to printed ids such as order numbers. |
| Adversarial review: a stray result=NOT_FOUND inside a live record, a timestamp tie decided by file number, and an analytics row without an email key each produced a false COMPLETE | Fixed in state.py and ledger.py with reproductions in adversarial_review.md; the 518 outputs did not change. The row verifier now also rejects duplicates, unfinished findings and citations of files that do not name the resource. |
| Request classifier treated 'please fix my billing address' as a deletion request (found by a custom case) | Added fix, amend, edit and modify to the correction verbs. The 518 outputs did not change. |

## Known limits

* The only gold answers are the 32 public samples. There is no gold for the 518 evaluation cases, so hidden-set accuracy is not measured and is expected to be below the sample numbers.
* All 14 missing sample steps are verification steps for resources that no evidence ties to the case: 7 anonymized analytics profiles, 5 deleted accounts and 2 audit records. Where the link is not forced we leave the step out rather than guess, so precision stays 1.0 and recall is 0.9275.
* Three evaluation cases (case_45, case_61, case_63) have no identifiable resource in admissible evidence and are answered COMPLETE with no steps. They are flagged in the run output.
* 30 resources that evidence ties to a case are left out of its answer because their state is unreadable or the contract has no operation for them. They are counted in the run output and listed in runs/audit.jsonl (see adversarial_review.md, open defect 1).
* The vision reader is evaluated on 15 files and is not wired into output.csv.
* The model cross-check can only disagree with the rules; it never changes a row. It found no disagreement.
